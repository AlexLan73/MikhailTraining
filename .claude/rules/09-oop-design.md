# 09 — ООП / SOLID / GRASP / GoF (стиль проектирования)

> Правило без `paths:` — **грузится всегда**. Введено 2026-08-16 по требованию Alex.
> Действует на весь новый код: `core/**`, `homework/**`, утилиты.

## 🔒 Жёсткие правила

1. **Только ООП.** Свободная функция допустима лишь как приватный хелпер внутри модуля своего класса.
2. **Один класс = один файл.** Имя файла = `snake_case` от имени класса.
   **Исключения** (и только они): конфигурационные модули (`config/`) и перечисления (`enums/`,
   `Enum`) — их состав обсуждается отдельно с Alex.
3. Класс > ~120 строк или файл > ~150 строк → **разбить**, это сигнал нарушения SRP.
4. Данные, пересекающие границу потока/процесса/слоя — **immutable**
   (`@dataclass(frozen=True, slots=True)`), это Value Object.
5. Зависимости объявляются как `typing.Protocol`. Конкретика связывается **только** в
   Composition Root (`run_hw.py`, `homework/hwNN_*/task.py`, `__main__.py`) — никаких `import`
   конкретного класса в бизнес-логике.
6. **Глобального состояния нет.** Singleton допустим только как явное архитектурное решение,
   спрятанное за `Protocol`, с возможностью подмены в тестах (DI).
7. `if/elif` по типу/категории — запрещён. Вместо него Polymorphism, Strategy или
   Chain of Responsibility.
8. `print()` — только в слое вывода. В остальном коде — логгер.

## 🔌 Публичное API модуля (решение Alex, 2026-08-16)

У каждого модуля — **один** файл с контрактом (`<name>_protocol.py` или `Protocol` рядом с классом).
Это и есть публичное API; всё остальное — детали реализации, наружу торчит только фасад
в `__init__.py`.

```python
class TokenMeter(Protocol):          # аналог C#-интерфейса IFoo
    def start(self, label: str) -> None: ...
    def stop(self) -> None: ...

    @property
    def total(self) -> TokenTotals: ...    # НЕ get_total()/set_total()
```

| C#-привычка | Как в Python | Почему |
|---|---|---|
| `IFoo` | `class Foo(Protocol)` | не требует наследования, проверяется `mypy` |
| `GetX()` / `SetX(v)` | `@property` → `obj.x`, `obj.x = v` | геттеры-сеттеры в Python — это свойства |
| явная реализация интерфейса | структурная типизация | подмена в тестах без каркаса моков |

Префикс `I` не пишем.

## 🔒 Владение данными между потоками (вместо «заморозки»)

- Объект наполняет **один** поток-владелец. **После `put()` в очередь объект не изменяется.**
  Копии и `freeze()` не нужны — `queue.Queue` расставляет барьеры памяти.
- Конфигурация, которую читают все потоки, — **строго `frozen=True`** и собирается один раз на старте.

## 🧭 SOLID — что проверять на ревью

| Принцип | Вопрос к коду |
|---|---|
| SRP | у класса одна причина изменения? загрузка ≠ алгоритм ≠ метрика ≠ вывод |
| OCP | новая разновидность = **новый класс**, а не правка существующего? |
| LSP | реализации одного `Protocol` взаимозаменяемы и не бросают наружу неожиданных исключений? |
| ISP | интерфейс не заставляет реализовать лишнее? (разделить по ролям) |
| DIP | верхний слой зависит от абстракции, а не от конкретного класса? |

## 🧩 GRASP — обязательный набор

Information Expert · Creator · Controller · Low Coupling · High Cohesion · Polymorphism ·
Pure Fabrication · Indirection · Protected Variations.

Практика: интерфейс ставим вокруг всего, что заведомо будет меняться (парсер, чекер, рендер,
хранилище, источник данных).

## 🏗️ GoF — рабочая палитра проекта

| Паттерн | Типичное место в репозитории |
|---|---|
| Strategy | модель, метрика, визуализатор, парсер, рендерер |
| Template Method | `HomeworkTask.run` (скелет прогона) |
| Registry | реестр ДЗ (`homework/registry.py`) |
| Facade | `DataContext`, оркестраторы утилит |
| Value Object | `Settings`, `ProjectPaths`, результаты и события |
| Singleton | только общая шина/пул процесса, за `Protocol` |
| Observer | потребление событий из шины |
| Chain of Responsibility | цепочки правил (валидация аргументов, классификация) |
| Builder | пошаговая сборка отчётов |
| Factory Method | выбор реализации по конфигу/доступности библиотеки |
| Adapter | обёртка внешнего инструмента (`subprocess`, сторонний API) |
| Null Object | отключённая опция без `if x is not None` |
| Command | единица работы для пула потоков |

## 🧪 Тест-гейт (пошаговая разработка)

- Работа режется на **независимые логические шаги**.
- **Следующий шаг не начинается, пока тесты текущего не зелёные** (`pytest -q`).
- Тест доказывает свойство/инвариант, а не «печатает».
- Правила тестирования → `04-testing-python.md` (pytest — стандарт проекта).

# 08 — ML-эксперименты: воспроизводимость, данные, веса

> **paths:** `homework/**`, `core/models/**`, `core/data/**`

## 🎲 Воспроизводимость (обязательно)

- Сид **один** на прогон: `common.seed.set_seed(ctx.seed)` в начале `HomeworkTask.run`.
  Фиксирует `random`, `numpy`, `torch` (если установлен).
- Дефолт — `Settings.seed = 42`. Меняем только осознанно и пишем в README ДЗ.
- Никаких `random`/`time`-зависимостей внутри `core/` — сид приходит снаружи (DI).
- Сплит train/val/test — детерминированный (сид + сохранённые индексы), не «каждый раз новый».

## 📦 Данные

- Датасеты живут в `data/` — каталог **в .gitignore**. В git идёт только `data/README.md`
  (откуда качать, размер, чем распаковать) и мелкие игрушечные примеры (<100 КБ).
- Нет датасета → ДЗ говорит понятную ошибку «скачай отсюда», тест → `pytest.skip(...)`.
- Крупные скачивания (>600 МБ) — только по явному «качай» от Alex, с полным списком файлов
  и суммарным объёмом сразу (Alex возит SSD дом↔работа, второго рейса нет).

## 💾 Артефакты прогона

- Всё, что генерит прогон (PNG, CSV, логи, веса) → `out/hwNN/`. Каталог **в .gitignore**.
- Веса моделей (`*.pt`, `*.pth`, `*.onnx`, `*.ckpt`) в git **не коммитим**.
- Нужно показать результат в репо — вставь **числа** в README ДЗ, а не бинарник.

## 📊 Метрики

- Метрика считается **одной** функцией из `core/metrics/` — не переписывать в каждом ДЗ.
- В отчёт (`HomeworkReport.metrics`) кладём числа, а не строки: `{"accuracy": 0.931}`.
- Сравнение с эталоном (sklearn/numpy) — хотя бы один тест на новую метрику.
- Честность: если результат хуже ожидаемого — пишем как есть + гипотезу почему.

## 🧪 Обучение

- Долгие прогоны — с явным логом эпох и возможностью `--epochs N` (быстрый смоук).
- Чекпойнт после обучения → `out/hwNN/model.pt`, путь через `ctx.out_dir`, не хардкод.
- Early stopping / расписание LR — параметры в конфиге ДЗ, не магические числа в цикле.

# 07 — Математика и модели — ТОЛЬКО в core/ (не в ноутбуке, не в JS)

> Правило без `paths:` — **грузится всегда**. Критическое (прецедент radar3d 2026-07-19).

## Правило

Любая **математика и модели** (формулы, преобразования координат, метрики, слои сети,
проекция/камера для визуализации) пишутся **только в `core/`** как ООП
(Value Object / Strategy, SOLID / GRASP / GoF) + тесты `pytest`.

`homework/`, ноутбуки Jupyter и веб-визуализация (в т.ч. **JS внутри HTML**) —
**тонкий слой показа** поверх `core`. Без собственной математики.
Без дублирования формул в двух местах.

## Почему (прецедент 2026-07-19, radar3d web-панель)

3D-проекция была размазана по JS демо: знаки осей заданы в ДВУХ местах.
Источник конвенции не один → рассинхрон → **зеркальность** → часы правок СЛЕДСТВИЯ
(инверсии, clamp) вместо ПРИЧИНЫ. Причина одна: **не было единой модели** (одного источника истины).

## Как правильно (СРАЗУ, а не после костылей)

1. **Единая модель сразу** — один источник истины. Не костылять локальными
   инверсиями/подгонками «по месту» — это лечение симптома.
2. Формула живёт в одном классе/функции `core/`, все потребители зовут её.
3. Ноутбук/скрипт ДЗ — только «загрузил → позвал core → показал».
4. **Тест доказывает свойство** (инвариант, диапазон, сходимость на игрушке),
   а не подгоняется под скриншот.

## Сигнал «стоп, ты костыляешь»

Если правишь одно место и ломается другое (знак, порядок, масштаб) — **остановись**:
это дублированный источник истины. Вынеси в единый объект в `core/`, не подкручивай следствие.

## 🔹 Шаг 0 — фиксация старта

1. Записать время старта, текущее смещение (число строк) в JSONL-транскрипте сессии
   (`~/.claude/projects/<проект>/<session>.jsonl`) **и список уже существующих файлов**
   `<session>/subagents/agent-*.jsonl` — новые после старта = агенты этого прогона (T-15, D18).
2. `git status` — зафиксировать список изменённых файлов до старта (для приёмки по `git diff`);
   агенты не коммитят.
3. Проверить окружение: `python -V`, наличие `pytest`, `git`; отсутствующие зависимости
   hw01 (`markdown-it-py`, `mdit-py-plugins`, `GitPython`, `PyYAML`) — доложить Alex,
   **не ставить молча** (extra `hw01` заводит T-01; после него — `pip install -e .[hw01]` по ОК Alex).
   🔧 р5: `ruff`/`mypy` могут отсутствовать в `.venv` — тогда пункт приёмки «ruff/mypy» пропускается с пометкой
   в отчёте, ставятся вместе с `.[hw01]` (`pip install -e .[hw01,dev]`) по тому же ОК.
4. 🔧 р5: `python` = `.venv/Scripts/python` (Windows) / `.venv/bin/python` (Debian); агентам передавать команду
   `python -m pytest tests/hw01/test_<модуль>.py -q` (не голый `pytest` — он может резолвиться в другой интерпретатор).

## 🔹 Шаг 2 — запуск агента

```
Agent(subagent_type: "general-purpose", model: "opus", description: "TASK=<id> <модуль>", prompt: …)
```
Агенты запускаются в фоне сами (отдельного флага нет); все агенты волны — **одним сообщением**,
чтобы шли параллельно; результат приходит уведомлением, ждать без опроса.

В промпт агента вложить целиком:

1. **первой строкой** ярлык `TASK=<id>` (по нему `tokenstat` относит файл агента к таску);
2. спеку разработки и тестирования (`hw01_mdscan_dev_test_spec_2026-08-16.md`) —
   как минимум разделы 2 (включая **2.5 — чьи контракты**), 3, 6, 7;
3. текст его таска: цель · файлы · контракт · что сделать · тесты · DoD · запрещено;
4. пути к части 1 (D-номера из таска) и части 2 (C4, §2 конфиг, §6 инварианты) — читать по ссылкам таска;
5. запрет трогать файлы других тасков и `tests/hw01/conftest.py` (кроме T-02); чужой контракт —
   импортировать, не переопределять; нашёл чужую ошибку → пиши в отчёт, не правь;
6. форму отчёта (раздел 7 спеки разработки и тестирования);
7. 🔧 р5: **среда**: корень репо, `python` из `.venv`, Python 3.14 дома / 3.12 на Debian, Windows-пути в коде запрещены;
   в одной волне чужой `Protocol` реализуется структурно (файла соседа ещё нет); исключения — только из `core/mdscan/errors.py`;
   агент **не коммитит**, не ставит пакеты, не пишет в `.claude/worktrees/*`;
8. 🔧 р5: если агент вернул отчёт с «Отклонения» по контракту — это **не** принимается молча: либо возврат, либо вопрос Alex.

## 🔹 Шаг 3 — приёмка (делает скил, не агент)

Цифрам агента на слово **не верить**. По каждому таску:

- [ ] прочитать `git diff` — изменены только файлы этого таска (и `conftest.py` только у T-02);
- [ ] **самому** запустить `pytest tests/hw01/test_<модуль>.py -q` и увидеть зелёное;
      T-10 / T-11 / T-13 — **5 раз подряд**, флаки = возврат;
- [ ] сверить публичный контракт с таском и частью 2 C4; чужие контракты (§2.5) не переопределены;
- [ ] проверить, что нет `TestRunner`, `pytest.skip` вместо реальных проверок, реальной сети,
      `time.sleep` для синхронизации, `join()` без таймаута;
- [ ] `ruff check` и `mypy` по файлам таска (если установлены; иначе — пометка в отчёте);
- [ ] 🔧 р5: агент не создал своих исключений (только `errors.py`), не импортировал `tests/` из продуктивного кода,
      не трогал `homework/hw01_mdlinks/__init__.py` (кроме T-14) и `core/mdscan/__init__.py` (кроме T-01/T-13);
- [ ] падение → вернуть агенту с текстом ошибки через `SendMessage` (тот же агент, контекст цел);
      **не более 2 возвратов**, дальше — к Alex.

## 🚫 Ограничения

- Реальная сеть в тестах запрещена: HTTP — только `127.0.0.1`, GitHub — заглушки.
- Не писать в `.claude/worktrees/*` (правило 03).
- Не коммитить и не пушить без явного «делай» от Alex.
- Не менять контракты `Protocol` из спеки (§2.5 — чей контракт). Расхождение → остановиться и спросить Alex.
- Не переходить к волне N+1, пока хоть один таск волны N не принят: следующая волна импортирует
  контракты предыдущей.
- **Гейт исполнения**: после каждой волны показать Alex результат и дождаться приёмки,
  прежде чем запускать следующую (`.claude/rules/10-execution-gate.md`).

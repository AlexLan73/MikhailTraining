## 🔹 Шаг 2 — запуск агента

```

```
🔧 р6: параметра `run_in_background` у `Agent` **нет** (та же ошибка была в ревью 4) — агенты и так идут в фоне;
все агенты волны — **одним сообщением** (несколько вызовов `Agent` подряд), результат приходит уведомлением, не опрашивать.
Агент упал на лимите сессии (`API error: session limit`) → проверить `git status`, что он ничего не оставил, и
перезапустить **тем же промптом** (так было с T-13 на этапе 1).

В промпт агента вложить целиком:

1. **первой строкой** ярлык `TASK=H-XX` — по нему считаются токены;
2. раздел 0 «Читай это, если ты исполнитель» из файла тасков (запреты, форма замера, **§0.4 среда**);
3. текст его таска дословно — по шагам, ничего не сокращая;
4. пути к спекам: этап 2 (§2 замеры и гипотезы), dev/test (разделы 2, 3, 6, 7), архитектура (раздел 0, §6) —
   читать `Read`, не пересказывать;
5. список файлов, которые агент **вправе** менять (из таска и таблицы волн), и явный запрет на остальные;
6. напоминание: **архитектуру и контракты не менять**, без замера оптимизация не принимается,
   не коммитить, не ставить пакеты, не писать в `.claude/worktrees/*`.

## 🔹 Шаг 4 — учёт токенов (обязательно; 🔧 р6: числа **попадают в отчёт**, а не только в чат)

После каждой волны и в конце прогона:

```bash
python -m core.tokenstat --since out/hw01/build_start.txt --label hw01-h --out out/hw01
```
🔧 р6: CLI добавлен (`core/tokenstat/__main__.py`), имя файла `tokens_<дата>_<время>.md` он строит сам; из кода —

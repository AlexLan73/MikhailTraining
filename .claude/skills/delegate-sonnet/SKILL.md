# delegate-sonnet — протокол делегирования Sonnet (MikhailTraining)

Реализацию (написание кода) отдаём **Sonnet** (беречь токены Opus), Кодо (Opus) пишет ТЗ,
делает **глубокое ревью** диффа и координирует. Триггер: `/delegate-sonnet` или «отдай Sonnet».

## 🔹 Схема (жёстко)

`Кодо разведка/ТЗ → Sonnet код (Agent, фон) → глубокое ревью Кодо (дифф + сам гонит тесты) → приём/коммит`

- **Разведка ДО ТЗ (Кодо):** прочитать условие ДЗ и реальные файлы `core/`, найти существующее
  (НЕ плодить), сверить контракт `HomeworkTask`. ТЗ пишется по факту кода, не по памяти.
- **Запуск:** `Agent(subagent_type: "general-purpose", model: "sonnet", run_in_background: true)`.
- **Ревью (Кодо, не на веру):** прочитать `git diff`, **самому** прогнать
  `pytest` (+ `python tests/all_test.py` для legacy) и `python run_hw.py hwNN`,
  сделать независимый smoke метрики.
- **Обрыв связи:** агенты иногда падают на обрыве (API error). Кодо **дочитывает состояние**
  (`git status`/`git diff`) и **доделывает сама** — не перезапускает с нуля.
- **Не верить отчёту на слово** — цифры Sonnet перепроверять.

## 🔹 Шаблон ТЗ (секции — заполнять все)

```
# КОНТЕКСТ / ПРОБЛЕМА
<какое ДЗ, условие курса, ссылка на homework/hwNN_*/README.md>

# ЖЁСТКИЕ ПРАВИЛА
✅ Тесты — pytest (функции test_*, assert, fixtures, parametrize; правило 04).
   Legacy-наборы на common.runner.TestRunner НЕ переписывать без явной задачи.
🚫 НЕ писать в .claude/worktrees/ (правило 03) — только корень репо.
🚫 Математика/метрики — в core/, ДЗ = тонкая оркестровка (правило 07).
🚫 Не коммитить датасеты/веса; артефакты только в out/hwNN/ (правило 08).
🚫 Не менять условие ДЗ «для удобства».
Python≥3.11, type hints, докстринги по-русски, ООП/SOLID (Strategy/ABC/VO как в соседях).
Не мутировать входы. Сид через common.seed.set_seed(ctx.seed). Имена строчные ASCII.
Интерпретатор: .venv/Scripts/python.exe (Windows) / .venv/bin/python (Debian).

# СНАЧАЛА ПРОЧИТАЙ (не гадай про API)
homework/registry.py (контракт HomeworkTask/HomeworkContext/HomeworkReport)
homework/hw00_intro/task.py (образец), core/metrics/, core/data/, tests/test_homework.py
Проверь grep, что метрика/загрузчик ещё НЕ существует (не плодить).

# ЧТО СДЕЛАТЬ
<нумерованные пункты: файлы, классы, контракты, точные формулы/сигнатуры>

# ПРОВЕРКА (обязательно, привести вывод)
python run_hw.py hwNN
pytest
python tests/all_test.py        # legacy-наборы
+ smoke ключевой метрики против эталона (в отчёт, не коммить).

# ОТЧЁТ
1. Что создано/изменено. 2. Вывод проверок (ok/fail/skip). 3. Метрики. 4. Честные девиации.
```

## 🔹 Приёмка (чек-лист Кодо после Sonnet)

- [ ] `git diff` прочитан, правки соответствуют ТЗ (без «отсебятины»).
- [ ] `run_hw.py hwNN` отрабатывает, метрики совпали с отчётом (прогнать самому).
- [ ] `pytest` зелёный (и `tests/all_test.py` для legacy-наборов).
- [ ] ДЗ зарегистрировано в `homework/registry.py`, README ДЗ заполнен (условие/метрики/выводы).
- [ ] Ничего лишнего не в git (данные, веса, PNG).
- [ ] Обновить `MemoryBank/tasks/IN_PROGRESS.md` + `MASTER_INDEX.md`.

## 🚫 Чего НЕ делать

- ❌ Не запускать Sonnet без разведки (прочитать код/контракт ДО ТЗ).
- ❌ Не коммитить/пушить без явного «закоммить/запушь» от Alex.
- ❌ Не верить цифрам Sonnet — перепроверять самому.
- ❌ Не делать `git add -A` не глянув `git status`.

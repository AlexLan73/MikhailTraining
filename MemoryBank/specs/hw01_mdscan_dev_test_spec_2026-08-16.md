## 1. Что считается «модулем»

Модуль — самостоятельный кусок системы с **одним публичным контрактом** и **своим тестовым файлом**.

| Признак | Требование |
|---|---|
| Публичное API | один файл-контракт (`*_protocol.py` или `Protocol` рядом с классом) |
| Внутренности | классы по одному в файле; наружу из пакета торчит только фасад в `__init__.py` |
| Зависимости | только через `Protocol` чужих модулей, никогда — на конкретные классы |
| Тесты | ровно один файл `tests/hw01/test_<модуль>.py` |
| Готовность | зелёный `pytest tests/hw01/test_<модуль>.py -q` + выполнены критерии раздела 6 |

Модуль **не готов**, пока его нельзя проверить в одиночку, без остальных.

## 2. Правила разработки

### 2.1 Стиль (основание — `.claude/rules/09-oop-design.md`)

- Только ООП; свободная функция — лишь приватный хелпер в модуле своего класса.
- **Один класс = один файл**; исключения: конфиг-модули, `Enum` и 🔧 р5 — **исключения пакета**
  (`core/mdscan/errors.py`, владелец T-01; свои классы исключений в модулях не заводить).
- Класс > ~120 строк или файл > ~150 строк → разбить.
- Type hints везде; докстринги по-русски; `print()` — только в слое вывода.
- `@property` вместо `get_x()/set_x()`; префикс `I` у интерфейсов не используем.
- Python ≥ 3.11, `pathlib`, никаких абсолютных Windows-путей в коде.
- Связывание конкретных реализаций — только в Composition Root (`__main__.py`, `task.py`).

### 2.2 Данные и потоки

- Объект наполняет **один** поток-владелец; **после `put()` в очередь объект не изменяется**
  (правило владения, D15.2). Копий и `freeze()` нет.
- Конфигурация, которую читают все потоки (`ScanConfig`), — `frozen=True`, собирается один раз.
- Завершение — **только по сентинелам**; `qsize()` в логике завершения запрещён.
- `task_done()` — строго **после** `put()` и в каждой ветке, включая ошибочную.

### 2.3 Исключения и логирование (`.claude/rules/11-exceptions-logging.md`, D2.1)

- Ни одно исключение не уходит «в никуда»: перехват → лог `ERROR` с трейсом → понятный результат
  (например, `result.error`) → работа продолжается.
- Голый `except:` и `except Exception: pass` — запрещены.
- Логируется каждый шаг: старт, репозиторий, файл в очереди, разобранный файл,
  **каждая ссылка** (`OK` → `DEBUG`, `BROKEN`/`TIMEOUT` → `WARNING`), итоги.
- Уровень по умолчанию `INFO`, иначе на 10 000 файлов лог станет гигабайтным.

Опциональная: `rich` (есть fallback). Новую зависимость **не вводить** без согласования с Alex.

## 3. Стратегия тестирования

### 3.1 Уровни

| Уровень | Что проверяет | Где |
|---|---|---|
| **Модульный** | контракт одного класса: границы, ошибки, инварианты | `test_<модуль>.py` каждого таска |
| **Интеграционный** | связка модулей на дереве-фикстуре (обход → разбор → проверка → отчёт) | `test_orchestrator.py` |
| **Свойства прогона** | детерминизм, отсутствие зависаний, завершение потоков | `test_pipeline.py`, `test_orchestrator.py` |
| **Качество** | точность извлечения и классификации на эталоне | `test_parsing.py` (пороги), `test_hw01_task.py` (метрики) |

### 3.2 Жёсткие запреты

| Запрет | Почему |
|---|---|
| `common.runner.TestRunner` | стандарт проекта — `pytest` (правило 04) |
| Реальная сеть | флаки и зависимость от интернета: HTTP только `127.0.0.1`, GitHub — заглушки |
| `time.sleep()` для синхронизации | флаки; ждать через `Event`/`join(timeout=…)` |
| Тест «печатает» вместо проверки | тест обязан доказывать свойство |
| Порядок тестов имеет значение | каждый тест самодостаточен |
| Общее изменяемое состояние между тестами | глобального состояния в проекте нет (D2, Singleton снят); появилось — это дефект, а не повод для фикстуры сброса |

### 3.3 Обязательные приёмы

- **Параметризация** (`@pytest.mark.parametrize`) — для таблиц «вход → ожидание» с читаемыми `id`.
- **`tmp_path`** — для любых файлов теста; в репозиторий тесты не пишут.
- **`pytest.approx`** — для сравнения float.
- **`pytest.raises(..., match=...)`** — проверять не только тип исключения, но и текст.
- **`monkeypatch`** — подмена внешних вызовов (`gh`, `git`, сеть); моков-«заглушек на всё» избегать.
  🔧 р5: предпочтительнее — внешний вызов инжектируется в конструктор (`run_gh`, `http_get`, `clock`), тест передаёт заглушку.
- **Заглушки чужих `Protocol`** — простые классы с нужными методами (duck typing), без наследования от контракта.
- **`pytest.importorskip` / `pytest.skip`** — когда нет `git` или необязательной библиотеки.
- **Таймаут в тестах конвейера** — любой `join()` вызывается с таймаутом, иначе тест виснет вместо падения.
- **Управляемое время** — для TTL/таймеров передавать `clock` в конструктор (T-11), не `sleep`.

### 3.4 Тестовые данные

| Набор | Что | Где строится |
|---|---|---|
| **A — эталонное дерево** | ≈25–30 файлов, ≈80 ссылок, ровно 7 битых, все «злые» случаи | `out/hw01/fixture_tree/` |
| **B — генерируемое дерево** | 200–500 файлов по сиду, для нагрузки и `speedup` | `out/hw01/gen_tree/` |
| Ожидания набора A | число файлов, ссылок по категориям, список `(rel_path, target, kind)` | `homework/hw01_mdlinks/support/expectations.py` (рядом с генератором, не json) 🔧 р5 |

Оба набора строит код (`FixtureTreeBuilder`), в git не попадают: каталог `out/` игнорируется.
Существующий каталог переиспользуется; `pytest --rebuild-fixtures` пересоздаёт (часть 1 D1).

### 3.5 Локальный HTTP-сервер для тестов

Один фикстурный `http.server` на `127.0.0.1` с эндпоинтами:
`/ok` → 200 · `/moved` → 301 · `/missing` → 404 · `/boom` → 500 · `/hang` → не отвечает (для `TIMEOUT`) ·
счётчик запросов (для проверки кэша) · режим «405 на HEAD» (проверка fallback на GET) ·
режим «403 без `User-Agent`» (проверка `http.user_agent`) · счётчик одновременных запросов (семафор).
Живёт в `tests/hw01/support/http_server.py` (T-07), поднимается фикстурой в `test_checking.py`.

## 5. Отладка модуля (что делать, когда красное)

1. **Читать реальный вывод pytest целиком**, а не последнюю строку.
2. Воспроизвести минимальным тестом: один вход — одно ожидание.
3. Проверить границу модуля: не лезет ли он в чужую ответственность (частая причина).
4. Для конвейера: если тест виснет — это отсутствующий `task_done()` или сентинел не дошёл;
   ставить `join(timeout=…)` и печатать `threading.enumerate()`.
5. Для флаки: гонять `pytest ... -q` **5 раз подряд**; нестабильный тест = дефект, а не «бывает».
6. Не «чинить» тест под код: если ожидание в ТЗ, а код другой — прав ТЗ.
7. Нашёл дефект в чужом модуле — **не править**, записать в отчёт.

## 6. Критерии готовности модуля (Definition of Done)

- [ ] Реализованы **все** пункты «что сделать» своего таска, ничего сверх.
- [ ] Публичный контракт совпадает со спекой дословно (имена, сигнатуры, возвращаемые типы);
      чужие контракты (§2.5) — импортированы, не переопределены.
- [ ] `pytest tests/hw01/test_<модуль>.py -q` — зелёный, 5 запусков подряд без флаки.
- [ ] Все перечисленные в таске тесты присутствуют (по номерам) и реально проверяют, а не печатают.
- [ ] Ошибки обрабатываются по разделу 2.3; голых `except` нет.
- [ ] Реальной сети в тестах нет; файлы тестов пишутся только в `tmp_path` / `out/`.
- [ ] Изменены **только** файлы своего таска (проверяется по `git diff`).
- [ ] `ruff check` и `mypy` по своим файлам без ошибок.
- [ ] Отчёт агента заполнен по форме (раздел 7).

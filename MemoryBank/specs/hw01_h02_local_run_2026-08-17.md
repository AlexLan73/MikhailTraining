### Секция «HTTP 401/403/429 — вероятно защита от ботов или лимит»

Заполнена **всеми семью** битыми HTTP-ссылками; секция «Битые HTTP-ссылки» при этом пустая — значит
других причин отказа (404 / 5xx / DNS) на этой цели не случилось.

| домен | код | шт. |
|---|---|---|
| `developers.redhat.com` | 403 | 1 |
| `huggingface.co` (`/settings/tokens`) | **401** | 1 |
| `image-ppubs.uspto.gov` | 403 | 3 |
| `gitlab.kitware.com` | 403 | 1 |
| `dl.acm.org` | 403 | 1 |

Профиль тот же, что в боевом прогоне организации (H-01): научные/издательские порталы и портал патентов
отбивают запрос без браузерного `User-Agent`. Ложных «битых» среди них нет — ссылки живые, доступ закрыт.

### Таймауты

организации. Воспроизводимо; статус отделён от `BROKEN` корректно.

| метрика | a (без сети) | b (сеть) | c (сеть + вложенные) |
|---|---|---|---|

| local / anchor / github / url / wikilink / footnote | 817 / 85 / 40 / 117 / 4 / 0 | 817 / 85 / 40 / 117 / 4 / 0 | 1963 / 467 / 76 / 270 / 449 / 38 |
| BROKEN локальных | 288 | 288 | 604 |
| BROKEN якорей | 24 | 24 | 81 |
| BROKEN HTTP | **0** | **7** | **37** |
| TIMEOUT | **0** | **1** | **3** |
| `broken_total` | 312 | 320 | 725 |

**a → b (что даёт сеть).** Набор файлов и ссылок **идентичен** — сеть не влияет на обход и разбор, только
на проверку. 157 ссылок (40 `github` + 117 `url`) переехали из `skipped` в реальные исходы: 149 `OK`,
7 `BROKEN` (401/403 — защита от ботов), 1 `TIMEOUT`. Цена — **+12.4 с** (×2.7): это ожидание ответов
внешних серверов, ради которого и существуют `http.workers = 10`. Локальные и якорные результаты
в точности те же — детерминизм соблюдён.

**b → c (что дают вложенные репозитории).** +10 репозиториев, +783 файла (1629 против 846), +2200 ссылок.
Это **не** ошибка обхода, а прямое следствие устройства цели: `core/`, `spectrum/`, `stats/`,
`signal_generators/`, `heterodyne/`, `linalg/`, `radar/`, `strategies/`, `DSP/` — самостоятельные
git-репозитории, **явно перечисленные в `.gitignore` главного репозитория**. Пока
`include_nested_repos: false`, их файлы не видит ни `git ls-files` главного репо, ни обход (их отсекает
`NestedRepoFinder`). При `true` каждый становится отдельным `RepoInfo` со **своим** `.gitignore`.

Поштучная сверка (git против ФС) сходится ровно:

```text
846 (главный) + 399 + 64 + 55 + 18 + 31 + 63 + 37 + 57 + 20 + 39 = 1629 = md_files_total прогона c
```

а 1634 − 1629 = **5** — это ровно те `.md`, которые игнорирует git (см. §6).

Резкий рост `wikilink` (4 → 449) и появление `footnote_url` (0 → 38) целиком дают файлы worktree-копии:
это старый снимок `MemoryBank/`, где использовался wiki-синтаксис.

Пропускная способность в c (56.1 файла/с) **выше**, чем в b (42.9): у субрепозиториев ссылок на файл
меньше, а HTTP-кэш ко второй половине прогона уже прогрет — время растёт не пропорционально числу файлов
(+92 % файлов дали +47 % времени).

**Локальные битые.** 288 → 604, но доля битых при этом **упала** (0.294 → 0.222): субрепозитории
документированы аккуратнее, чем архивные каталоги `MemoryBank/tasks/**/_superseded/` главного репо,
дающие основную массу битых ссылок на перемещённые файлы.

## 8. Дефекты и наблюдения

### Д-1 · 🔴 `data:`-URI классифицируется как локальная ссылка и раздувает отчёт

**Где**: `core/mdscan/parsing/link_classifier.py` (цепочка правил), `core/mdscan/parsing/rules/rule_local_path.py`,
печать — `core/mdscan/reporting/markdown_report_builder.py`.
**Что**: `LocalPathRule` — тотальное правило, срабатывает последним и ловит **всё**, что не подошло
предыдущим восьми. Встроенная картинка вида `![](data:image/png;base64,iVBOR…)` попадает в категорию
`local`, проверяется как путь на диске, признаётся `BROKEN` и **целиком** печатается в таблицу
«Битые локальные ссылки» — дважды (колонки «цель» и «причина»).
**Последствие**: строка на 1.8 МБ, отчёт c раздут в 16 раз; в статистике — ложный битый локальный линк.
**Предложение**: правило `RuleDataUri` (или общее «известная чужая схема»: `data:`, `javascript:`,
`chrome-extension:`) **перед** `LocalPathRule`, статус `SKIPPED`; независимо от этого — ограничить длину
`target`/`detail` в построителе отчёта (например, 200 символов + `…`), чтобы **любая** аномальная цель не
ломала отчёт. Не правил — чужой модуль (T-06 / T-12).

### Д-2 · 🟠 `std::string`, `af::array` и т.п. считаются битыми локальными ссылками

**Где**: те же файлы, та же причина — тотальный `LocalPathRule`.
**Что**: в автогенерированной документации `.rag/dsp-gpu/**/L2_symbols/*.md` C++-символы оформлены как
ссылки вида `[std::string](std::string)`. Классификатор трактует их как относительные пути → 5 ложных
`BROKEN` в каждом прогоне.
**Последствие**: небольшое, но это ложная тревога в отчёте, который человек читает как «список того, что чинить».
**Предложение**: обсудить с Alex — либо правило «цель содержит `::` и не содержит `/`» → `UNKNOWN`/`SKIPPED`,
либо оставить как есть и задокументировать. Не правил.

### Д-3 · 🟠 `include_nested_repos: true` обходит `.gitignore` **родителя** и подхватывает git-worktree

**Где**: `core/mdscan/discovery/nested_repo_finder.py` + `core/mdscan/runtime/pipeline_runner.py::_queue_files`.
**Что**: `NestedRepoFinder` ищет `.git` по файловой системе, не спрашивая git. Поэтому при `true` в список
репозиториев попадает `.claude/worktrees/youthful-brattain-89a8fb` — **git-worktree того же самого
репозитория** (`.git` здесь файл `gitdir: …/.git/worktrees/…`), причём каталог `.claude/worktrees/`
**явно перечислен в `.gitignore`** цели. Итог: 399 файлов и 594 ссылки старого снимка того же проекта
попали в статистику как «ещё один репозиторий» — 24 % всех файлов прогона c.
**Замечание по факту**: сами субрепозитории (`core/`, `spectrum/`, …) тоже перечислены в `.gitignore`
родителя, и их включение при `true` — как раз то, чего просит флаг. Но worktree того же репо — почти
наверняка не то, чего хотел пользователь.
**Предложение**: отличать worktree/submodule от самостоятельного клона по содержимому файла `.git`
(`gitdir:` указывает внутрь `<root>/.git/`) и по умолчанию их пропускать; либо честно документировать
поведение в `Doc/Modules/mdscan/CLI.md`. Не правил.

### Д-4 · 🟡 `broken_total` включает `TIMEOUT`

**Факт**: прогон b — `broken_local 288 + broken_anchor 24 + broken_http 7 = 319`, а `broken_total = 320`;
прогон c — `604 + 81 + 37 = 722` против `broken_total = 725` при `timeout_http = 3`. Разница ровно равна
числу таймаутов. Совпадает с уже известным кандидатом ревью (`MdFileResult.broken_count` включает
`TIMEOUT`) — фиксирую как подтверждение на реальных данных, чтобы H-11 не открывал заново.

### Д-5 · 🟡 Секция «Битые HTTP-ссылки» пуста, хотя `broken_http = 7`

**Факт (прогон b)**: все 7 отказов — коды 401/403, они уехали в отдельную секцию «HTTP 401/403/429», а
основная секция показывает `_нет_`. Поведение соответствует решению Alex (спека этапа §1.2 п.1), но
читатель отчёта видит «битых HTTP нет» при `broken_http = 7` в счётчиках — противоречие на глаз.
**Предложение** (косметика, для H-12): в пустой секции писать не `_нет_`, а
`_нет; все N — в секции «HTTP 401/403/429»_`. Не правил.

### Н-1 · ℹ️ `file://` корректно уходит в `SKIPPED`

Прогон c: 6 локальных ссылок в статусе `skipped` — это `file://`-адреса (`LocalFileChecker`: «абсолютный
адрес чужой машины»). Ложных битых от них нет, поведение соответствует р5.

### Н-2 · ℹ️ Ни одного `ERROR` / `CRITICAL` за три прогона

1490 + 1507 + 3121 строк лога, `ERROR` / `CRITICAL` = 0. 624 / 641 / 1452 `WARNING` — это битые ссылки и
якоря, т.е. штатный уровень по правилу 11. Ни один из 1629 файлов не дал ошибки чтения
(`files_failed = 0`), включая пути с кириллицей и пробелами.

### Н-3 · ℹ️ `mdscan.yaml`

Файл создаётся в **рабочем каталоге запуска** (D19.1). Все прогоны сделаны из корня репозитория курса, где
`mdscan.yaml` числится в `.gitignore` (`/mdscan.yaml`) — в git не попадает. На момент закрытия таска файла
в корне нет. Из каталога цели сканер **не запускался** — чужой репозиторий не засорён.

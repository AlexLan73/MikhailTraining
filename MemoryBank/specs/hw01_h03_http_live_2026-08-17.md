зачем `TIMEOUT` отделён: по нему видно, что таймаут занижен, а не что ссылка мёртвая (D11).

## 5. Кэш: один сетевой запрос на URL

В наборе по два вхождения `https://example.com/` и `https://www.python.org/`. Сравнение `DEBUG`-логов
прогона 1 (кэш включён) и прогона 3 (`-http.cache:false`) по времени обработки **дубля**:

| URL | кэш включён (прогон 1) | кэш выключен (прогон 3) |
|---|---|---|
| `https://example.com/` (2-е вхождение) | **0 мс** (`08:08:43,787` → `43,787`) | **182 мс** (`08:10:15,278` → `15,460`) |
| `https://www.python.org/` (2-е вхождение) | **1 мс** (`43,787` → `43,788`) | **166 мс** (`15,460` → `15,626`) |

Вывод: при `http.cache: true` повторный адрес обслуживается из словаря `HttpChecker._cache` без сетевого
вызова — **один запрос на URL за прогон** (инвариант 22). При выключенном кэше дубль стоит полного запроса.
Тот же инвариант закрыт модульным тестом на локальном сервере (`test_same_url_requested_once`,
`tests/hw01/test_checking.py`, счётчик обращений сервера = 1).

## 6. Замечания и дефекты (код не правил)

1. **`http.timeout_ms` не ограничивает разрешение имени (DNS).** Ссылка #7 (`.invalid`) ждала ответа
   резолвера **~11–12 с** в обоих прогонах: 12.0 с при `timeout_ms: 2000` и 11.1 с при `timeout_ms: 100`
   (по меткам `DEBUG`-лога). `socket.getaddrinfo` таймаутом `urlopen` не покрывается — это поведение
   стандартной библиотеки, а не дефект `HttpChecker`. Последствие: один несуществующий домен добавляет
   ~12 с к длительности прогона независимо от настройки. Предложение (не реализовывал): предупреждение
   в `Doc/Modules/mdscan/CLI.md`; ограничивать по-настоящему — только отдельным резолвом имени со своим
   таймаутом, это смена поведения и требует решения Alex.
2. **`timeout_ms` — бюджет одной сетевой операции, а не всего запроса.** В прогоне 2 при 100 мс
   `https://github.com/AlexLan73` и `https://gist.github.com/` ушли в `TIMEOUT`, а `http://github.com/`
   (редирект 301 → https, то есть **больше** работы) вернул 200: каждое новое соединение в цепочке
   редиректов получает таймаут заново. Отдельно: `urllib` переходит по 301 **сам**, поэтому в отчёте
   виден только конечный код 200 — сам факт редиректа нигде не фиксируется. Для условия ДЗ («проверить
   доступность») это допустимо; если понадобится показывать 301 — нужен свой `HTTPRedirectHandler`.
3. **`httpbin.org` не годится как источник живого 404** — с этой машины он не отвечает за 2000 мс
   (`https://httpbin.org/status/404` → `TIMEOUT`). Рабочий живой 404 дал GitHub
   (`https://github.com/AlexLan73/no-such-repo-xyz-h03` → `BROKEN 404`). В тестах `test_http_live.py`
   httpbin поэтому не используется.
4. **Попадание в кэш не отличимо в логе.** `HttpChecker.check` пишет одну и ту же строку
   `http 200 <url> (из <файл>)` и для сетевого запроса, и для ответа из кэша; отличить можно только
   по времени между строками. Предложение (не реализовывал, 1 строка в `check`): при попадании
   в кэш писать `_log.debug("http %s %s (кэш, из %s)", ...)`. Кандидат в находки H-11.
5. **Локальные ссылки в секции «Таймауты» появиться не могут** — секция строится по всем категориям
   (`frozenset(LinkKind)`), но `LocalFileChecker` статус `TIMEOUT` не выставляет. Дефекта нет, фиксирую как факт.

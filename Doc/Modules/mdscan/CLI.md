## 1. Форма вызова и закон CLI

```bash
python -m core.mdscan <цель> [-поле:значение ...]
```

```text
1. Аргументов НЕТ          → печатаем конфигурацию и выходим, код 0.
2. Аргументов ≥ 1          → ПЕРВЫЙ аргумент ВСЕГДА цель (4 ветки).
3. Первый не подходит      → ошибка, код 2.
   ни под одну ветку
4. Остальные аргументы     → только -поле:значение, порядок любой.
```

Единственное исключение: `-h`, `--help`, `-?` первым аргументом = как без аргументов.

Флагов вида `--workers 8` в утилите нет намеренно: любое поле конфигурации задаётся одним и тем же
способом `-путь.к.полю:значение`, так что документировать нужно один механизм, а не два.

### 1.1 Четыре ветки цели

| Ветка | Первый аргумент | Что сканируем | Как определяется |
|---|---|---|---|
| локальный каталог | `../DSP-GPU`, `/home/alex/proj`, `.` | папку на диске | путь существует и это каталог |
| один репозиторий | `git@github.com:org/repo.git`, `https://…/repo.git` | клонируем (`--depth 1`) и сканируем | URL кончается на `.git` или содержит `<org>/<repo>` |
| организация | `https://github.com/dsp-gpu` | все репозитории организации | URL вида `https://github.com/<имя>` без репозитория |
| слово `yaml` | буквально `yaml` | цели из конфига: `source.target` и/или `source.repositories` | точное совпадение со словом |

Спорный случай (например, каталог с именем `yaml`) снимается явным `-source.kind:local`.

Каталоги лога и отчёта **не позиционные** — задаются полями `-logging.dir:…` и `-report.dir:…`.
Имена файлов формируются всегда сами: `<scope>_<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>.log` и `.md`,
метка времени одна на прогон.

### 1.2 Матрица аргументов

| Что передано | Поведение | Код |
|---|---|---|
| ничего | вывести всю конфигурацию и примеры | `0` |
| `-h` / `--help` / `-?` | то же самое | `0` |
| цель [+ `-поле:значение` …] | сканировать; остальное из yaml и defaults | `0` / `1` |
| первый аргумент не подходит ни под одну ветку (например `-workers.parse:8`) | «первым аргументом должна быть цель: каталог, URL или слово yaml» | `2` |
| второй позиционный аргумент | «лишний аргумент; каталоги задаются как `-logging.dir:…` / `-report.dir:…`» | `2` |
| `-поле:значение` с неизвестным полем | ошибка с подсказкой «похожие поля: …» | `2` |

Разбор `-поле:значение`: режется по **первому** двоеточию, путь к полю — через точку, тип берётся
из значения по умолчанию (`int`, `float`, `bool`, `str`, список через запятую). Поэтому
`-report.title:Итоги: dsp-gpu` даёт заголовок `Итоги: dsp-gpu`, а не ошибку.

## 2. Цепочка валидации V1…V10

Правила выполняются по порядку, первый не-`ok` останавливает цепочку (Chain of Responsibility,
класс на правило, `core/mdscan/cli/validation/`).

| # | Класс | Что проверяет | Код при нарушении |
|---|---|---|---|
| V1 | `ArgCountRule` | позиционный аргумент ровно один или ни одного | 2 |
| V2 | `FirstArgIsTargetRule` | если аргументы есть — первый обязан быть целью (одна из 4 веток) | 2 |
| V3 | `OverrideSyntaxRule` | каждый `-поле:значение` разобран, поле существует, тип приводится; **здесь же переопределения применяются** к черновику | 2 |
| V4 | `PathNormalizationRule` | `~`, относительные пути, пробелы, кириллица, UNC → абсолютный `Path` | — |
| V5 | `TargetKindRule` | определяет вид **каждой** цели и пишет `source.targets_resolved`; при `source.kind != auto` берёт указанный вид без детекции | 2 |
| V6 | `PathIsDirectoryRule` | локальная цель — каталог (`.git` → поднимаемся к родителю) | 2 |
| V7 | `PathReadableRule` | есть право на чтение | 2 |
| V8 | `GitRepositoryRule` | цель внутри git; нет — предупреждение, работаем как с папкой | 0 (warning) |
| V9 | `OutputDirRule` | `logging.dir` и `report.dir` — каталоги, создаются при отсутствии | 2 |
| V10 | `WritePermissionRule` | пробная запись в эти каталоги удалась | 2 |

Порядок важен и менять его нельзя: V3 идёт **до** V9/V10, потому что `-logging.dir:…` может
прийти из командной строки; V4 (нормализация) — до всех проверок существования.

При `-h` и при запуске без аргументов правила V4…V10 не выполняются: цели нет, каталоги не
создаются. При коде 2 лог и отчёт не создаются вовсе — единственное, что может появиться на диске,
это `mdscan.yaml` холодного старта (он читается до цепочки).

Вид цели определяется **один раз** — правилом V5. `SourceFactory` его только читает и никогда
не переопределяет: один источник истины.

## 3. Коды возврата

| Код | Значение |
|---|---|
| `0` | успех, битых ссылок нет (или `run.fail_on_broken: false`) |
| `1` | успех, найдены битые ссылки или файлы с ошибками |
| `2` | ошибка аргументов или конфигурации |
| `3` | внутренняя ошибка (нет `git`, не удалось записать отчёт) — в логе строка `CRITICAL` |

`run.fail_on_broken: false` переводит `1` в `0` — и только это; содержимое отчёта и консоли
не меняется.

## 4. `mdscan.yaml` — холодный старт

Файл ищется в **каталоге запуска**. Если его нет, он создаётся автоматически со всеми значениями
по умолчанию **и с комментариями** — править конфигурацию можно, не заглядывая в документацию.
Факт создания пишется в лог уровнем `INFO`.

Приоритет значений:

```text
defaults (код)  <  mdscan.yaml  <  командная строка
```

Источник каждого поля видно в печати конфигурации: `d` = defaults, `y` = yaml, `c` = cmdline.

Единственное место, где живут значения по умолчанию, — `core/mdscan/config/defaults.py`.
Служебного поля `source.targets_resolved` в yaml нет: его заполняет V5, задать ключом
`-source.targets_resolved:` нельзя (`UnknownFieldError`).

## 5. Все параметры конфигурации

Тип берётся из значения по умолчанию — им же определяется приведение в `-поле:значение`.

### `source` — что сканируем и откуда берём репозитории

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `source.target` | `''` | str | цель прогона; сюда подставляется первый аргумент CLI | постоянная цель, чтобы не писать её каждый раз (`... yaml`) |
| `source.repositories` | `[]` | список str | список целей при цели `yaml`; можно смешивать папки, репозитории, организации | набор из разных организаций; работа без API; часть организации |
| `source.kind` | `auto` | str | как трактуется цель: `auto` · `local` · `remote_repo` · `github_org` | автоопределение ошиблось (каталог с именем `yaml`) |
| `source.discovery` | `auto` | str | чем раскрываем **организацию** в список репозиториев: `auto` (`gh`, затем REST API) · `gh` · `api` | нужен воспроизводимый строгий режим, а не тихий переход на другой путь |
| `source.auth` | `auto` | str | протокол доступа: `auto` · `ssh` · `https` · `token` | чужая публичная организация → `https`; CI без ключа → `token` |
| `source.visibility` | `all` | str | какие репозитории организации брать: `all` · `public` · `private` | отсечь шум |
| `source.include_forks` | `false` | bool | тащить ли форки | нужен и форкнутый код |
| `source.include_archived` | `false` | bool | тащить ли архивные репозитории | аудит всего, включая архив |
| `source.page_size` | `100` | int | размер страницы GitHub API (листаем до конца) | тонкая настройка под лимиты |
| `source.clone_dir` | `out/hw01/_clones` | str | куда клонируются удалённые репозитории | мало места на диске проекта |
| `source.clone_depth` | `1` | int | глубина клона | нужна история, а не только последний коммит |
| `source.keep_clones` | `false` | bool | удалять ли клоны после прогона (`cleanup()`) | отладка клона — оставить |

Правило согласования с законом CLI: **цель** — это первый аргумент, а `source.*` описывает
**способ раскрытия** цели. Слово `yaml` — тоже цель («возьми её из конфига»). Если заполнены и
`target`, и `repositories`, сканируется всё вместе; дубли отсекает реестр. Если при цели `yaml`
пусты оба — ошибка «цель не задана», код 2.

### `scan` — что ищем внутри репозитория

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `scan.include_nested_repos` | `false` | bool | попадают ли вложенные репозитории (submodule, worktree, клон внутри) | нужен вендорный код внутри проекта |
| `scan.md_extensions` | `['.md', '.markdown']` | список str | какие файлы считаем Markdown | нестандартные расширения (`.mdx`) |
| `scan.respect_gitignore` | `true` | bool | `true` — список от `git ls-files --cached --others --exclude-standard`; `false` или папка вне git — обычный `rglob` | проверить и `build/`; **обязательно `false`, если цель лежит внутри игнорируемого каталога** (например `out/`) |

### `workers` — параллельность

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `workers.discover` | `5` | int | сколько репозиториев обходится и клонируется одновременно | много репозиториев в организации; лимиты GitHub — снижать |
| `workers.parse` | `5` | int | сколько `.md`-файлов разбирается одновременно | тысячи файлов и сеть — поднимать; слабый CPU — снижать |

Третье число параллельности — `http.workers`: это семафор внутри стадии 2, а не третий пул.

### `parser` — как разбираем Markdown

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `parser.preset` | `gfm-like` | str | набор правил `markdown-it-py`: `commonmark` · `gfm-like` (таблицы, автоссылки) | нужен строгий CommonMark |
| `parser.plugins` | `['footnote', 'attrs', 'wikilinks']` | список str | какие ссылки вообще будут найдены | не нужны Obsidian-вики или сноски |

Два подводных камня. `wikilinks` — **не** плагин `mdit-py-plugins` (такого там нет), а встроенное
inline-правило экстрактора; имя в списке работает как флаг его включения. Пресет `gfm-like`
включает `linkify` только при установленном `linkify-it-py` — без него голые URL перестают быть
ссылками, поэтому пакет входит в extra `hw01`.

### `checks` — что проверяем у найденных ссылок

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `checks.local` | `true` | bool | проверяем ли существование локальных файлов | быстрый черновой прогон |
| `checks.anchors` | `true` | bool | проверяем ли якоря (`#раздел` в своём файле, `a.md#раздел` в целевом) | документация с генерируемыми якорями |

### `http` — проверка внешних ссылок

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `http.enabled` | `true` | bool | ходим ли в сеть; `false` — внешние ссылки только считаем (`SKIPPED`) | работа без сети, CI, тесты |
| `http.timeout_ms` | `2000` | int | сколько ждём ответ | медленные хосты — поднять (меньше ложных `TIMEOUT`), быстрый прогон — снизить |
| `http.workers` | `5` | int | семафор: сколько HTTP-запросов идёт одновременно (общий на прогон) | сайт отвечает `429` — снижать |
| `http.method` | `head_then_get` | str | сначала `HEAD`, при `405/501` повтор `GET` | сервер не любит `HEAD` |
| `http.cache` | `true` | bool | один и тот же URL за прогон проверяется один раз | отладка чекера |
| `http.user_agent` | `mdscan/0.1` | str | заголовок `User-Agent` | сайт отдаёт `403` на дефолтный `Python-urllib` |

### `progress` — ход работы на экране (stderr)

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `progress.enabled` | `true` | bool | показываем ли прогресс вообще | CI без терминала → `false` |
| `progress.interval_sec` | `1.0` | float | как часто перерисовывается строка состояния (зона 1) | длинный прогон — реже |
| `progress.style` | `line` | str | вид зоны 1: `line` · `panel` · `off` | вкус |
| `progress.message_lines` | `1` | int | сколько строк-сообщений от модулей держим на экране (зона 2) | хочется видеть больше событий |
| `progress.message_ttl_sec` | `5.0` | float | через сколько секунд строка-сообщение гаснет сама | сообщения мелькают слишком быстро |

Не-TTY определяется сам: при перенаправлении вывода прогресс отключается независимо от настройки.

### `logging` — лог в файл

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `logging.enabled` | `true` | bool | пишем ли лог; `false` — файл не создаётся, вызовы логгера не падают | отладка «в чистом виде» |
| `logging.level` | `INFO` | str | `DEBUG` (каждая ссылка и файл) · `INFO` · `WARNING` (только проблемы) | разбор полёта → `DEBUG`; на 10 000 файлов лог станет огромным |
| `logging.dir` | `out/hw01` | str | каталог лога; имя файла строится само | отдельная папка под прогон |

### `report` — итоговый отчёт

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `report.dir` | `out/hw01` | str | каталог отчёта; имя файла — как у лога, с той же меткой времени | отдельная папка под прогон |
| `report.title` | `''` | str | заголовок отчёта; пусто — берётся из имени цели | несколько прогонов подряд, надо различать |
| `report.console` | `true` | bool | печатать ли итоговую таблицу в stdout | `run_hw.py` и CI печатают свою сводку → `false` |

### `run` — поведение прогона

| Параметр | Умолчание | Тип | На что влияет | Когда менять |
|---|---|---|---|---|
| `run.fail_on_broken` | `true` | bool | код возврата `1` при найденных битых ссылках | замер или разведка, падать не нужно → `false` |

## 6. Примеры

Печать всей конфигурации (шапка, usage, таблица «поле · значение · источник · описание»,
строка `цели (source.targets_resolved)`, примеры):

```bash
python -m core.mdscan
python -m core.mdscan -h
```

Локальная папка целиком:

```bash
python -m core.mdscan ../DSP-GPU
python -m core.mdscan .                     # текущий репозиторий
```

Подкаталог репозитория (файлы берутся только из него, `rel_path` и `web_url` считаются от
git-корня):

```bash
python -m core.mdscan Doc/Modules/mdscan -http.enabled:false -progress.enabled:false
```

Дерево внутри игнорируемого каталога — обязателен `-scan.respect_gitignore:false`, иначе
`git ls-files` не отдаст ни одного файла:

```bash
python -m core.mdscan out/hw01/fixture_tree -http.enabled:false -scan.respect_gitignore:false
```

Цели из конфига (`source.target` и/или `source.repositories`):

```yaml
# mdscan.yaml
source:
  repositories:
    - /home/alex/DSP-GPU                        # локальная папка
    - git@github.com:dsp-gpu/radar.git          # один приватный репозиторий
    - https://github.com/executablebooks        # чужая публичная организация целиком
  auth: https
```

```bash
python -m core.mdscan yaml
```

Организация целиком, разово поднять число потоков разбора:

```bash
python -m core.mdscan https://github.com/dsp-gpu -workers.parse:8
```

Прогон без сети (быстро, только локальные ссылки и якоря):

```bash
python -m core.mdscan . -http.enabled:false
```

Свои каталоги для лога и отчёта, лог подробнее, не падать на битых:

```bash
python -m core.mdscan . -logging.dir:out/hw01/logs -report.dir:out/hw01/reports \
                        -logging.level:DEBUG -run.fail_on_broken:false
```

Через обвязку ДЗ (строит фикстуры, делает три прогона, пишет `out/hw01/metrics.json`):

```bash
python run_hw.py hw01
```

## 7. Что получается на выходе

Каждый прогон оставляет **пару файлов с одинаковой меткой времени** в каталогах
`report.dir` и `logging.dir` (по умолчанию оба — `out/hw01/`, каталог `out/` в git не идёт):

```text
out/hw01/
├── fixture_tree_2026-08-17_03-50-22.md      отчёт
├── fixture_tree_2026-08-17_03-50-22.log     лог того же прогона
├── metrics.json                             метрики run_hw.py hw01
└── tokens_2026-08-17_03-51-18.md            отчёт core.tokenstat (к сканеру отношения не имеет)
```

Имя строится как `<scope>_<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>.<ext>`, где `scope` — хвост цели (имя каталога,
имя репозитория без `.git`, имя организации; для цели `yaml` — слово `yaml`). Пробелы заменяются
на `_`, запрещённые в именах файлов символы убираются, кириллица остаётся.

### 7.1 Секции Markdown-отчёта

| Секция | Что внутри |
|---|---|
| Прогон | время старта, длительность, код возврата |
| Цель | адрес и вид (`local` · `remote_repo` · `github_org`) |
| Репозитории | корень, `web_url`, признак вложенного |
| Статистика по типам ссылок | по каждой категории: всего · ok · broken · timeout · skipped |
| Счётчики прогона | те же числа, что уходят в `ScanSummary.counters` и в метрики ДЗ |
| Файлы | репозиторий · путь · сколько ссылок · статус · ошибка |
| Битые локальные ссылки | файл · строка · цель · причина |
| Битые HTTP-ссылки | файл · строка · цель · **код ответа** |
| Таймауты | отдельной секцией, не смешаны с битыми |
| Файлы с ошибками | путь и текст исключения (например `MarkdownReadError: … не UTF-8`) |

Отчёт детерминирован: два прогона на одном дереве дают одинаковый текст, кроме времени.
Пустая секция печатается явным «нет» — по отчёту всегда видно, что проверка выполнялась.

### 7.2 Консольная сводка

`report.console: true` печатает в **stdout** таблицу итогов и список битых ссылок со статус-кодами.
Есть `rich` — таблица цветная (`RichConsoleRenderer`), нет — ANSI-fallback
(`PlainConsoleRenderer`), содержимое то же. Прогресс при этом идёт в **stderr** и на stdout
не мешает: `python -m core.mdscan . > report.txt` даёт чистый файл.

### 7.3 Лог прогона

Шапка (по ней видно, что и как сканировалось), затем строки формата
`время | уровень | поток | repo | file | сообщение`:

```text
# scope       : fixture_tree (auto)
# started     : 2026-08-17 03:50:22
# input       : <абсолютный путь цели>
# workers     : discover=5 parse=5 http=5
# checks      : local=True anchors=True http=False nested=False
# report      : <путь к .md-отчёту того же прогона>
2026-08-17 03:50:22,407 | INFO | MainThread | - | - | конвейер запущен: parse-worker'ов 5
2026-08-17 03:50:22,410 | INFO | discover_0 | - | - | репозиторий: … (web=…)
2026-08-17 03:50:22,472 | INFO | parse-1 | MikhailTraining | docs/a.md | parsed links=3 broken=0 elapsed=50.7ms error=-
2026-08-17 03:50:22,485 | WARNING | parse-5 | MikhailTraining | docs/b.md | link broken kind=local target=… line=6 http=0 нет заголовка …
```

Поля `repo` и `file` подставляются модулями через `extra=`; их нет — печатается `-`.
Потоки именованные (`discover_N`, `parse-N`, `collector`), имя идёт в каждую строку — по нему
считается, сколько потоков разбора реально работало. Уровни: успех ссылки — `DEBUG`,
битая или таймаут — `WARNING`, ошибка чтения или разбора — `ERROR` с трейсом,
падение прогона — `CRITICAL`. Запись идёт через `QueueHandler` и `QueueListener`, поэтому воркеры
не блокируются на диске, а строки не перемешиваются.

## 8. Частые ситуации

| Симптом | Причина | Что сделать |
|---|---|---|
| «просканировано 0 файлов» на непустой папке | цель внутри игнорируемого каталога, `git ls-files` её не отдал | `-scan.respect_gitignore:false` |
| много ложных `BROKEN` на живых сайтах | сайт отвечает `403` на дефолтный `User-Agent` | `-http.user_agent:…` (по умолчанию уже свой) |
| много `TIMEOUT` | медленные хосты | `-http.timeout_ms:5000` |
| `429` от GitHub | слишком много одновременных запросов | снизить `-http.workers:` и `-workers.discover:` |
| прогон падает с кодом 2 и подсказкой «похожие поля» | опечатка в имени поля | сверить с `python -m core.mdscan` (печать конфигурации) |
| код 3 | нет `git` в `PATH` либо не удалось записать отчёт | поставить git; проверить права на `report.dir` |
| в CI лишний вывод | прогресс и сводка | `-progress.enabled:false -report.console:false` |
| нужен ненулевой код только при битых ссылках | так и работает по умолчанию | обратное — `-run.fail_on_broken:false` |

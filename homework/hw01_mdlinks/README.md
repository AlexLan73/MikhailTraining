# ДЗ 01 — CLI-утилита: Markdown Link & Dead Code Checker

## Условие

> Перенесено дословно из выданного файла курса «Домашнее задание 1».

### 🔧 CLI-утилита: Markdown Link & Dead Code Checker

**Суть:** Консольный скрипт на Python или Node.js, который сканирует указанную папку с проектом.

#### Функционал

- Находит все `.md` файлы в папке.
- Извлекает все ссылки `[text](url)` и `file:///...`.
- Проверяет локальные ссылки на существование файлов, а внешние HTTP-ссылки — на доступность
  (отправляет HEAD или GET запрос).
- Выводит красивый отчёт в консоль (с цветами/таблицей) со списком сломанных ссылок и статус-кодами.

#### На чём «споткнётся» ИИ без хорошей спеки

- Обработка относительных путей относительно текущего файла.
- Ограничение по таймаутам HTTP-запросов и обработка ошибок сети (404, 500, timeout).

## Что сделано

- **Пакет `core/mdscan/`** — вся логика сканера (правило 07: математика и модели в `core/`,
  ДЗ — тонкий слой). Наружу торчит один контракт `Scanner.scan(config) -> ScanSummary`
  ([`core/mdscan/scanner.py`](../../core/mdscan/scanner.py)); остальное — детали реализации.
- **Конфигурация** `mdscan.yaml`: приоритет `defaults (код) < yaml < командная строка`,
  переопределение любого поля ключом `-путь.к.полю:значение`, холодный старт создаёт файл
  с комментариями. Все значения по умолчанию — в одном месте
  ([`core/mdscan/config/defaults.py`](../../core/mdscan/config/defaults.py)).
- **CLI** (`python -m core.mdscan`): закон «первый аргумент — всегда цель» (каталог · URL
  репозитория · URL организации · слово `yaml`), цепочка из 10 правил валидации
  (Chain of Responsibility), коды возврата `0/1/2/3` и `130` при `Ctrl+C`.
- **Источники репозиториев**: локальный каталог, удалённый репозиторий (`clone --depth 1`),
  организация GitHub целиком (`gh repo list`, затем REST API; пагинация, фильтры forks/archived).
- **Обход**: правило ближайшего git-корня, `git ls-files --cached --others --exclude-standard`
  (уважает `.gitignore`, но видит новые файлы), вложенные репозитории по флагу,
  потокобезопасный реестр против дублей.
- **Двухстадийный конвейер**: пул `discover` → `TaskQueue` → parse-воркеры → `ResultQueue` →
  поток-сборщик. Два сентинела, `task_done()` строго после `put()`, завершение только по
  сентинелу — ни одного `join()` без таймаута, ни одной потерянной записи.
- **Парсинг** на `markdown-it-py` (пресет `gfm-like` + `footnote`, `attrs`, встроенное правило
  wikilinks): inline-, reference-, автоссылки, изображения, сноски, `[[wiki]]`; ссылки внутри
  fenced-кода не извлекаются; `linkify` (голые URL) — **только со схемой**, иначе `Full.md` и
  `conftest.py` превращались в URL. Классификация — цепочка из **10** правил
  (`WIKILINK → FOOTNOTE → ANCHOR → MAILTO → TEL → GITHUB → HTTP → FILE_URL → OTHER_SCHEME → LOCAL`):
  десятое правило `OtherSchemeRule` отправляет чужие схемы (`data:`, `javascript:`, `ftp:`, а заодно
  C++-символы вида `std::string`) в `UNKNOWN`/`SKIPPED`, а не в «локальный путь».
- **Чекеры**: `LocalFileChecker` (путь относительно **файла-владельца**), `AnchorChecker`
  (сверка по GitHub-slug, якорь в своём и в целевом файле, кэш заголовков),
  `HttpChecker` (`HEAD`, при `405/501` повтор `GET`, таймаут, семафор, кэш по URL,
  свой `User-Agent`), `NullChecker` для `mailto`/`tel`/`wikilink`/сносок и для выключенных проверок.
- **Отчёты**: Markdown-файл со всеми обязательными секциями (репозитории, статистика по типам,
  таблица файлов, битые локальные, битые HTTP с кодами, `TIMEOUT` отдельно, файлы с ошибками)
  и консольная сводка (`rich`, при его отсутствии — ANSI-fallback).
- **Прогресс и лог**: две зоны на `stderr` (статус по таймеру плюс строка-сообщение с TTL),
  лог через `QueueHandler`/`QueueListener` — воркеры не блокируются на диске; имена файлов
  `<scope>_<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>.log` и `.md`, метка времени одна на прогон.
- **Обвязка ДЗ**: `Hw01MdLinks(HomeworkTask)` плюс `Hw01Metrics` — генерация эталонного дерева
  (набор A) и большого сгенерированного (набор B), три прогона, метрики в `HomeworkReport`.
- **Учёт токенов**: отдельный модуль `core/tokenstat/` — читает JSONL-транскрипт сессии и
  файлы субагентов, считает токены по агентам и таскам, пишет `tokens_*.md`.
- **Тесты**: `tests/hw01/` — 17 файлов, **444 теста**, `pytest tests/hw01 -q` зелёный
  (плюс 4 `skipped` — живые HTTP-проверки, они идут только с `MDSCAN_NETWORK=1`);
  `mypy` — 0 ошибок на 141 файле, `ruff` чисто. Сети в обычных тестах нет (только `127.0.0.1`).

### Что добавил этап 2 (боевая приёмка и ускорение)

- **Прогон по живым данным**: организация GitHub `dsp-gpu` целиком, большой локальный репозиторий,
  живые HTTP-исходы `OK`/`BROKEN`/`TIMEOUT` — числа ниже в разделе «Метрики».
- **Ускорение одиночного прогона −36 %** (0.605 → 0.389 с на 500 файлах): блочный разбор заголовков
  вместо второго полного разбора `markdown-it`, обход на `os.scandir` с одним `resolve()` на файл
  (`ResolvedPathCache`), кэш базового каталога в `LocalFileChecker`, ленивое логирование.
- **Параллельное клонирование организации** (`clone_workers = workers.discover`): 45.2 → 31.5 с
  на `dsp-gpu` без HTTP.
- **Устойчивость**: `Ctrl+C` гасит конвейер за 0.32 с и даёт код возврата **130** с `CRITICAL`
  в логе вместо трейсбека и процесса, живущего минутами; при битом `.git` — откат на обход дерева.
- **Читаемость отчёта**: ячейки обрезаются до 200 символов (одна `data:`-картинка раздувала отчёт
  до 1.8 МБ в одной строке), коды `401/403/429` вынесены в секцию «вероятно защита от ботов»,
  битая ссылка логируется одной `WARNING`, попадание в HTTP-кэш видно в логе (`http cache`).
- **Умолчания параллельности** поднято 5 → **10** (`workers.parse`, `http.workers`), консольная
  сводка отключаема (`report.console`), у `python -m core.tokenstat` появился свой CLI.

## Как запустить

> Готовые отчёты реальных прогонов, метрики и токены — в [`results/`](results/README.md);
> все параметры конфигурации — [`mdscan.example.yaml`](mdscan.example.yaml) и `Doc/Modules/mdscan/CLI.md`.

Установка зависимостей ДЗ (`markdown-it-py`, `linkify-it-py`, `mdit-py-plugins`, `GitPython`,
`PyYAML`, `rich`) вместе с dev-набором:

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e .[hw01,dev]     # Windows
.venv/bin/python -m pip install -e .[hw01,dev]             # Debian
```

Домашнее задание целиком (строит наборы A и B, делает три прогона, пишет метрики
в `out/hw01/metrics.json`):

```bash
python run_hw.py hw01
```

Сканер как самостоятельная утилита:

```bash
python -m core.mdscan                                   # печать всей конфигурации, код 0
python -m core.mdscan .                                 # текущий репозиторий
python -m core.mdscan Doc/Modules/mdscan -http.enabled:false      # только локальные ссылки
python -m core.mdscan out/hw01/fixture_tree -http.enabled:false -scan.respect_gitignore:false
python -m core.mdscan git@github.com:dsp-gpu/radar.git  # один удалённый репозиторий
python -m core.mdscan https://github.com/dsp-gpu        # организация целиком
python -m core.mdscan yaml -workers.parse:8             # цели из mdscan.yaml плюс разовая правка
```

Первый аргумент — всегда цель, остальные — только `-поле:значение` в любом порядке.
Прерывание `Ctrl+C` гасит конвейер и возвращает код **130**.

Тесты модуля и учёт токенов:

```bash
pytest tests/hw01 -q                                  # 444 passed, 4 skipped (живая сеть)
MDSCAN_NETWORK=1 pytest -m network tests/hw01 -q      # 4 живые HTTP-проверки
python tests/hw01/support/bench_scan.py --workers 1 --repeat 5 --layers   # замер по слоям
python -m core.tokenstat --since out/hw01/build_start.txt --label hw01 --out out/hw01   # токены
```

### `speedup` в двух режимах — и где параллельность вообще работает

| режим | 1 поток | 5 потоков | 10 потоков | `speedup` |
|---|---:|---:|---:|---:|
| **без HTTP**, набор B, 500 файлов | 0.389 с | 0.403 с | 0.432 с | 0.96 / **0.90** |
| **с HTTP**, локальный сервер 30 мс, 300 файлов × 2 URL = 600 запросов | 25.07 с | 4.87 с | 2.61 с | ×5.15 / **×9.59** |
| **живая сеть**, 15 ссылок в 8 файлах | 19.78 с | — | 11.35 с | **×1.74** |
| живая сеть, те же 15 ссылок в **одном** файле | 20.75 с | — | 19.87 с | ×1.04 |

Три вывода, которые стоит держать в голове:

1. **Без сети потоки не ускоряют и не должны**: работа — чистый Python (`markdown-it`, `pathlib`)
   под GIL плюс короткие файловые вызовы. 10 потоков стоят ≈10 % времени; умолчание
   `workers.parse = 10` оправдано тем, что HTTP включён по умолчанию.
2. **С сетью масштабирование почти линейное** до `min(workers.parse, http.workers)` — пик
   одновременных запросов на локальном сервере ровно 1 / 5 / 10.
3. **Единица параллельной работы — файл, а не ссылка.** Один `.md` = одна задача одного потока,
   его ссылки проверяются последовательно: файл с 15 внешними ссылками не ускорится ни на 10
   потоках, ни на 100. Потолок на живой сети задаёт самая медленная ссылка — отказ DNS занимает
   10–12 с и `http.timeout_ms` его не покрывает.

### Устойчивость и нагрузка

| сценарий | что получилось |

| Нет сети (мёртвый прокси) | все 39 внешних ссылок → `TIMEOUT`, локальные проверены как обычно, прогон дошёл до отчёта, 0 `ERROR` |

|---:|---:|---:|---:|---:|---:|

| 5000 | 10087 | 3.255 с | 1536 | 24.6 МиБ | 785 КиБ |

Время растёт **строго линейно** (`0.078 с + 0.636 мс × N`, r² = 0.99997) и даже чуть лучше линейного:
цена одного файла падает с 0.78 до 0.65 мс. Память не течёт — три прогона подряд в одном процессе
дают один и тот же пик 28.0 МиБ и остаток 0.1 МиБ. Границы применимости: очереди без `maxsize`,
поэтому backlog доходит до 98 % дерева, а память — ≈4.6 КиБ на файл; экстраполяция на 100 000 файлов
даёт ≈64 с и ≈0.5 ГБ. `logging.level: DEBUG` на 5000 файлов — 67 739 строк, 8.6 МиБ и **×2** ко
времени прогона: умолчание `INFO` выбрано не случайно.

## Выводы

- Главный подводный камень условия — **относительные пути**: цель ссылки резолвится от папки
  файла-владельца (`md_file.parent`), а не от корня репозитория, иначе `../../README.md` из
  вложенного файла ломается на ровном месте. Отсюда и сигнатура `check(link, md_file)`:
  чекеру нужен файл, а не каталог, ведь якорь `#раздел` живёт в заголовках этого же файла.
- Второй камень — **сетевые исходы**: `TIMEOUT` намеренно отделён от `BROKEN`, это разные
  диагнозы (поднять таймаут против «ссылка мертва»), а `SKIPPED` — третий: `mailto:`, `tel:`,
  `file://` и выключенные проверки не должны попадать в статистику битых. Живой прогон это
  подтвердил: при таймауте 100 мс медленные адреса уезжают в `TIMEOUT`, а ошибка DNS остаётся
  `BROKEN` — по статусу видно, занижен таймаут или ссылка действительно мёртвая.
- **Параллельность честно не сработала без сети**: `speedup ≈ 0.90…0.95`. Разбор `markdown-it-py` —
  чистый Python под GIL, ускорять там нечего, остаются накладные на очереди. Зато **с сетью** —
  ×9.59 на 10 потоках (локальный сервер, 600 запросов): конвейер окупается ровно там, где воркеры
  ждут. И важная граница: единица параллельной работы — **файл**, поэтому один большой `.md` со
  множеством внешних ссылок не ускорится никаким числом потоков.
- **Ускорять надо то, что измерено, а не то, что кажется.** Первая картина «63 % времени — это
  `Path.resolve()`» оказалась артефактом `cProfile`: при потоках `cumtime` складывается повторно и
  показывал больше 100 % от общего времени. Прямые замеры `perf_counter` по слоям дали настоящее
  узкое место — **второй полный разбор файла ради заголовков** (0.108 с из 0.605 с). Блочный разбор
  плюс кэш резолва дали −36 %; погоня за «резолвом» не дала бы ничего.
- **Боевая приёмка нашла то, чего не находят тесты на фикстурах**: встроенная картинка
  `data:image/png;base64,…` классифицировалась как локальный путь и выбрасывала в отчёт строку на
  1.8 МБ (89 % объёма файла); `linkify` в fuzzy-режиме превращал `Full.md` и `conftest.py` в URL и
  давал 51 ложный битый линк; научные сайты и портал патентов отвечают `403` без браузерного
  `User-Agent` — это не битые ссылки, а бот-защита, и им нужна своя секция отчёта; отказ DNS стоит
  10–12 с и `http.timeout_ms` его не покрывает. Ни один из этих случаев не воспроизводится на
  сгенерированном дереве.
- Сканер споткнулся ровно там, где предупреждало условие, плюс на мелочах окружения: `file:///…`
  пришлось увести в `SKIPPED` (абсолютный путь чужой машины давал ложную битую ссылку), а файл
  с битым байтом — публиковать результатом с `error`, а не ронять им прогон.
- Модуль вышел вчетверо больше «скрипта на 200 строк», и это не оверинжиниринг, а цена
  требований: конфигурация, три источника репозиториев, лог, прогресс, отчёт. Зато условие
  закрыто целиком, а `f1 = 1.0` на эталонном дереве получен не подгонкой — ожидания зафиксированы
  генератором фикстур до того, как был написан парсер.
